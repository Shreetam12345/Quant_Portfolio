Mathematical Core

Key formulas implemented in Python + C++

Spread Construction
ε_t = P_A(t) − β·P_B(t)

β estimated via OLS. Tested for stationarity (ADF test). If I(0) → cointegrated.

OU Half-Life
τ₁/₂ = ln(2) / κ

κ from OLS of Δε_t on ε_t₋₁. Filter: 1 < τ < 120 days to ensure tradeable reversion.

Z-Score Entry
z_t = (ε_t − μ_w) / σ_w

Rolling window μ, σ. Entry |z| > 2.0, exit |z| < 0.5. ML filter removes ~20% false positives.

Pricing Mathematics

Black-Scholes, Monte Carlo GBM, and binomial tree

Black-Scholes Call
C = S·e⁻ᵍᵀ·N(d₁) − K·e⁻ʳᵀ·N(d₂)
d₁ = [ln(S/K) + (r+σ²/2)T] / σ√T
GBM Monte Carlo
S_T = S₀·exp[(r − σ²/2)T + σ√T·Z]

Antithetic pairs (Z, −Z) halve variance. 50k paths, 252 time steps.

CRR Binomial Tree
u = e^(σ√Δt), p = (e^(r·Δt)−d)/(u−d)

200-step tree with early exercise check at each node for American options.

GitHub → Render Deployment (5 Steps)
1

Create GitHub Repos

Push each project to its own public repo: github.com/you/quantalpha and github.com/you/algoforge. Include all files from the generated structure.

2

Connect to Render

Go to render.com → New → Blueprint. Select your GitHub repo. Render reads render.yaml automatically — no manual configuration.

3

PostgreSQL Auto-Provision

The render.yaml database block creates a free Postgres 16 instance. The DATABASE_URL env var is injected into the API service automatically.

4

Run SQL Schema

In Render dashboard → your database → Shell. Run: psql $DATABASE_URL -f sql/schema.sql to initialise tables and views.

5

Live URLs

API: https://quantalpha-api.onrender.com · Frontend: https://quantalpha-frontend.onrender.com. Free tier spins down after 15 min idle — use UptimeRobot to keep warm.
